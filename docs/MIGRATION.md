# Artifact migration map

Baseline inspected on 2026-10-04 in `APIs/apollo-deployment-api/apollo-artifact`, its BuildKit publisher and transports, and Node artifact integration. The classification column states the required destination for each behavior. The evidence column separately describes the old behavior, current Rust implementation, and qualification status. Source presence is not qualification. No behavior marked missing is considered ported. Keep the Zig implementation and its callers until the replacement has qualified and every caller has moved.

## Exact cutover and removal closure

The current service and protocol live under this standalone workspace: `Cargo.toml`, `crates/artifactd-protocol/`, `src/main.rs`, `src/cli.rs`, `src/api/`, and CAS/OCI/prepare modules. There are no Apollo sibling package dependencies in its manifest. That establishes package isolation in source, not caller cutover or a production release.

In `APIs/apollo-deployment-api`, replace and then remove the importer subprocess contract at `crates/apollo-buildkit-publisher/src/{publication,verification}.rs`, `crates/apollo-transports/src/buildkit/{process,solve,publication,recovery}.rs`, and `crates/apollo-control-plane/src/bootstrap/build_workers.rs`. Change `deploy/control-plane/build-worker.env.example`; update `scripts/build-buildkit-release.sh`, `scripts/stage-rust-build-worker.sh`, and proof/recording scripts that name `apollo-artifact-buildkit-import`, inspect receipt files, or simulate `--verify`. Replace the Zig Node dependency in `apollo-node/src/workload/artifact_{application,binding_store,identity,integration}.zig` and the Node build/dependency graph with the external client. Then remove `apollo-artifact/`, `apollo-artifact/tools/buildkit_import.zig`, the Artifact Zig protocol/import/process launch paths and every configured importer binary. Deletion follows qualification; it is not itself evidence of qualification.

## Current Rust completeness snapshot

Implemented in source: standalone daemon and CLI binaries; Linux Unix `SOCK_SEQPACKET` API with same-UID `SO_PEERCRED`, bounded packets and SCM_RIGHTS; generic operation/digest/pin/lease/prepared IDs; redb schema/intents; streaming local CAS; OCI layout archive admission, manifest/index graph validation and linux/amd64/linux/arm64 selection; DiffID-checked rootfs extraction, whiteouts, safe relative symlinks, deterministic prepared-tree verification; graph references and recoverable import/preparation/GC intents. Qualification artifacts include final Linux x86_64/arm64 release all-target builds and full suites, source-hash snapshots, isolated core churn/throughput/idle/state measurements, three fuzz targets with short macOS smoke runs, audit/deny/tree outputs, and a CycloneDX SBOM whose schema and dependency edges validate (`docs/sbom-validation.txt`). See [QUALIFICATION.md](QUALIFICATION.md) and retained native logs for exact coverage.

Explicitly missing in source: corrupt CAS repair; safe absolute BusyBox symlink rewriting; legacy SQLite migration; direct buildd and Node callers; generic BuildKit result integration; bounded durable operation retention without permanent exhaustion. GC live-root verification is not incrementally bounded by its candidate limit. Final native release builds, suites and core churn pass, but core churn is not daemon API/journal churn; disk-full/power-loss/full crash matrices, native long fuzz campaigns, complete registry qualification, dependency-policy warning review and independent release approval remain incomplete. Do not interpret the final native evidence as release approval. The existing `docs/RED_TEAM_ROUND_1.md`, `docs/RED_TEAM_ROUND_2.md`, `docs/RED_TEAM_ROUND_3.md`, `docs/SIMPLIFIER_ROUND_1.md`, `docs/SIMPLIFIER_ROUND_2.md` and `docs/PRIMARY_REVIEW.md` document open review/qualification findings; older “absent evidence” statements predate the newly recorded artifacts and should be read accordingly, not as a current inventory of logs.

Current registry/redb dependency evidence is recorded separately in `cargo-audit-redb-registry.json`, `cargo-audit-fuzz-redb-registry.json`, `cargo-deny-redb-registry.txt`, `cargo-tree-redb-registry.txt` and `sbom-validation-redb-registry.txt`. Historical native churn still describes baseline commit `3a42141`; it is not evidence for current redb/API journal churn.
