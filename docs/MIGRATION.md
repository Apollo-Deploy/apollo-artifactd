## Exact cutover and removal closure

The current service and protocol live under this standalone workspace: `Cargo.toml`, `crates/artifactd-protocol/`, `src/main.rs`, `src/cli.rs`, `src/api/`, and CAS/OCI/prepare modules. There are no Apollo sibling package dependencies in its manifest. That establishes package isolation in source, not caller cutover or a production release.

In `APIs/apollo-deployment-api`, the active Rust BuildKit publisher, transport and bootstrap send the archive FD to Rust artifactd; Node calls the same service through a Rust FFI client. Standalone `Open-Source/apollo-buildd` imports completed OCI output through its versioned artifactd client, persists import and optional push intents, and replays pending publication on startup. The old Zig package, importer, registry probe, API CI entry, importer-based proof wrapper, and cached Zig binaries have been removed. Historical dated proof records and the caller-owned `apollo-artifact-receipt-v1` schema remain as history/contracts, not runtime dependencies. Native builds and focused caller probes exist on x86_64 and ARM64, while composed solve/settlement, restart/fault, security, performance, and independent release qualification remain open. Source deletion is not evidence of qualification.
