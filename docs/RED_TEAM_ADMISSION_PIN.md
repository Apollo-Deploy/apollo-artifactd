# Red-team review: atomic OCI admission and pinning

Date: 2026-10-05  
Scope: uncommitted `src/oci/admission.rs`, pinned OCI archive import, and the
API dispatch path. This is an implementation review of admission/pin atomicity,
not a full release review.

## Verdict

`APOLLO_ARTIFACTD_PRODUCTION_BLOCKED`. The graph, roots, edges, and optional
pin are committed in one redb transaction, and the normal single-daemon replay
path is coherent. The previously reported transaction-boundary race is fixed;
the remaining verdict is broader release scope, not an observed admission-pin
defect.

## Resolved: pin conflict check moved inside the write transaction

The earlier review identified that the existing pin and reference count were
checked before the redb transaction. The current code performs both checks via
`StateTx` inside the transaction immediately before the graph and pin writes,
so the transaction view owns the identity decision and capacity check.

The store also takes an exclusive owner lock and exposes a single mutable
`Store` through the daemon, so the previously suggested second-Store race is
not an authorized public boundary and is not required evidence for this
serialized design. Same-ID/same-digest replay remains idempotent; a sequential
different-digest conflict remains rejected.

## Reviewed properties

- Graph edges, manifest roots, the selected OCI root, and the optional pin are
  written in the same redb transaction. Transaction failure cannot publish a
  partial graph through this path.
- Pin IDs are parsed as protocol `PinId`s before admission. Same-ID/same-
  digest retries are idempotent; same-ID/different-digest retries are rejected
  in the serialized case.
- `select` validates the requested platform, while graph construction visits
  all index manifests and verifies descriptor/platform/config relationships.
  Pinning an index therefore protects its reachable multi-platform graph.
- Archive import streams and verifies each named blob before admission. A
  later archive failure or pin conflict can leave unrooted, already verified
  CAS blobs, which is recoverable GC state rather than a partial graph
  publication; this path still needs the broader crash/fault qualification.
- GC epoch dirtiness is generated by the transactional writes to roots, edges,
  and pins, so a successful admission invalidates an in-progress mark cycle.

## Evidence boundary

The public `admission_pin` test exercises replay, sequential pin conflict,
restart, GC retention, and unpin collection. This report does not infer full
native admission/fault qualification from that focused test. Full registry,
GC, recovery, churn, caller-cutover, and old-Zig removal gates remain open.
