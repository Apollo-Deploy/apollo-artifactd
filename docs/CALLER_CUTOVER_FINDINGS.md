# Caller cutover findings

This is a read-only inventory of the current caller seams and a required cutover sequence. It records source facts and gaps; it does not claim an integration is implemented or qualified. Do not remove the Zig Artifact implementation or its callers until the replacement has passed the integration and recovery gates below.

## Current source seams

The API repository at `APIs/apollo-deployment-api` currently has a process chain rather than a direct artifactd client:

- `crates/apollo-transports/src/buildkit/process.rs::publisher_command` launches the configured publisher and passes `--artifact-importer`, `--store-root`, `--oci-tar`, `--receipt`, BuildAttempt ID, SourceSnapshot ID, and source-bundle digest as arguments.
- `crates/apollo-buildkit-publisher/src/publication.rs::ArtifactPublisher::publish` reads/reuses a receipt, invokes the configured importer with filesystem paths, and retries failures. `verification.rs::verify_admitted_graph` launches that importer with `--verify`.
- `crates/apollo-transports/src/buildkit/solve.rs::run_attempt_inner` waits for the publisher process and converts its receipt into `BuilderArtifactPublication` through `publication.rs`.
- `crates/apollo-transports/src/buildkit/recovery.rs::recover_publication` replays publication when a solve-success marker exists without a receipt; otherwise it reads the receipt, then separately launches importer verification.
- The process/config seam is `BuildKitExecutorConfiguration.artifact_importer` in `crates/apollo-transports/src/buildkit/{mod,configuration}.rs` and `APOLLO_ARTIFACT_IMPORTER_BIN` in `crates/apollo-control-plane/src/bootstrap/build_workers.rs` and `deploy/control-plane/build-worker.env.example`.
- `scripts/build-buildkit-release.sh` builds/stages `apollo-artifact-buildkit-import`; `scripts/stage-rust-build-worker.sh` requires/stages it. BuildKit proof and evidence scripts also assert importer binaries, `--verify`, and `artifact-receipt.json` files. These contracts need caller-owned replacements before those paths can be removed.

The standalone Rust `apollo-buildd` workspace has `src/artifact/{mod.rs,transport.rs}` with allocation, OCI archive import, pull, and push helpers. `tests/artifact_boundary.rs::real_artifactd_fd_import_and_replay` is an ignored real-daemon test. A source search found no production build/solve callsite for these helpers, so this module is currently a protocol adapter and test seam, not a production integration. `src/state/mutations.rs` persists `Build.artifact_operation` as a deterministic 64-hex caller correlation value; it is not an artifactd-allocated operation token.

The standalone daemon and protocol sources are `apollo-artifactd/crates/artifactd-protocol/src/{lib.rs,client.rs,wire.rs}` and `apollo-artifactd/src/{api/dispatch.rs,oci/archive.rs,oci/mod.rs}`. The API version is 2. Open-Source buildd currently duplicates the wire request/response/action definitions and seqpacket/SCM_RIGHTS transport in `src/artifact/{mod.rs,transport.rs}`. Its VERSION=2 JSON for allocation, archive import, and response is presently shape-compatible with the daemon, but the duplicated copies can drift. Buildd maps its own `Digest` type and business state around the protocol; the artifactd protocol crate uses generic digest and identity types.

## Required semantics and concrete gaps

1. **Keep business provenance with the caller.** The legacy `ArtifactReceipt` in `crates/apollo-buildkit-publisher/src/receipt.rs` binds `BuildAttemptId`, `SourceSnapshotId`, optional source-bundle digest, selected OCI facts, and a canonical payload digest. Those Apollo build IDs must remain in buildd's state/receipt and must never be added to artifactd requests or state. Artifactd should return generic verified facts. The current archive-import facts contain artifact/index digest, selected manifest digest, config digest, layer digests, and platform (`apollo-artifactd/src/oci/mod.rs::facts`); they do not contain descriptor sizes/media types or the caller receipt/provenance digest. Existing `BuilderArtifactPublication` conversion also needs manifest/config/layer sizes, media information, graph size/count, and receipt-derived provenance fields (`crates/apollo-transports/src/buildkit/publication.rs`). Either return those verified generic descriptor facts from artifactd or inspect each referenced blob and have buildd construct and hash its own receipt. Do not interpret the artifactd operation journal response as a build receipt.

2. **Persist the artifactd token before import.** The caller's 64-hex `artifact_operation` is useful as a durable correlation/index but cannot be sent as a mutation token: artifactd allocates tokens of form `<32 lowercase hex>_<20 decimal digits>`. Buildd must request allocation, durably store the returned token against its own build attempt before sending OCI import, and reuse precisely that token after timeout/restart. A lost allocation response must cause a fresh allocation only if no mutation could have been sent; ambiguous import outcomes must replay/query with the persisted token. The existing adapter's `allocate_operation`/`import_oci_archive` demonstrates the client-side shape but no production caller persists this mapping.

3. **Transfer the archive through an FD.** BuildKit's current caller passes `--oci-tar` path to a subprocess. The direct protocol action is `Action::ImportOciArchive { platform }` plus one read-only regular-file FD over SCM_RIGHTS. The buildd adapter already validates a caller-owned, private, bounded FD and seeks it to offset zero; the daemon checks input descriptor type and byte bound. The production integration must open the completed archive without following symlinks, verify it remains the expected private regular file, then pass its descriptor instead of a path or file contents in JSON. No tar bytes or credentials belong in command-line arguments or protocol logs.

4. **Resolve service identity and socket authorization first.** `apollo-artifactd/src/api/mod.rs::serve` creates a mode-0600 socket and accepts only peers whose `SO_PEERCRED.uid` equals artifactd's effective UID. The buildd adapter also rejects root and requires peer UID and input-file owner to equal the buildd caller UID. This currently works only when both processes share one unprivileged UID. If they run under separate dedicated identities, preserve `SO_PEERCRED` but add an explicit narrowly scoped client-UID authorization and matching socket/group access policy; settle who owns or stages the OCI FD so it passes the actual trust checks. Do not loosen checks globally or make the socket world-accessible.

5. **Make import admission and pin atomic with respect to GC.** Implemented on the artifactd side: `IMPORT_OCI` and `IMPORT_OCI_ARCHIVE` accept an optional caller-provided generic `PinId`, and verified graph edges/roots plus the pin commit together before the result is returned. OCI classification/edges alone do not keep content live. Caller cutover still must supply and durably retain that PinId, then release it only when caller lifecycle state authorizes release. A separate import followed by `PIN` remains unsafe for publication. Public daemon qualification covers FD archive admission, GC, conflict, restart/replay and unpin; actual buildd crash/receipt integration remains required.

6. **Replace process recovery with protocol recovery.** The old publisher retry/recovery scheme is in `apollo-buildkit-publisher/src/publication.rs` and `apollo-transports/src/buildkit/recovery.rs`; it recovers from a solve-success marker, receipt file, and importer `--verify`. The new caller must persist its allocated artifactd token and a solve-complete marker, replay the same import action after a lost response/restart, validate returned facts, then atomically write its own receipt/outcome. On restart with a persisted receipt, verify artifactd content using protocol operations and confirm the receipt's caller IDs match the recovered build. There must be no publisher-to-importer or buildd-to-importer subprocess bridge.

7. **Package the protocol boundary independently.** `apollo-artifactd`'s Cargo workspace has `crates/artifactd-protocol` as a member and the daemon depends only on that local protocol crate plus external Rust crates. Keep that property: no dependency from the daemon package back to buildd or another Apollo package. Buildd should consume the generic protocol crate as a versioned standalone dependency or as an explicitly vendored standalone crate in its own source/release bundle; do not rely on an undeclared checkout-relative sibling path in production packaging. Remove buildd's duplicate `ImportRequest`, `ImportAction`, `ImportResponse`, `Platform`, and low-level transport only after all caller code has moved to the shared contract. Retain a small caller adapter for buildd policy, its domain `Digest`, durable correlation, references, and receipt construction.

8. **Move the actual caller before deleting the legacy implementation.** Wire direct artifactd client calls into the real successful OCI-export path in `apollo-buildd` and its durable state/recovery; the existing module/test alone does not satisfy this. The API repository's `apollo-transports/src/buildkit` flow is a separate legacy caller and must either be migrated to the new buildd owner or replaced with the direct protocol adapter; it must not keep launching the old publisher/importer. The later Node consumer (`apollo-node/src/workload/artifact_{application,binding_store,identity,integration}.zig`) must separately move its binding, pin, lease, prepare, and release lifecycle to artifactd. Build-specific IDs and workload identities stay in their respective callers. Remove `apollo-artifact/`, `apollo-artifact/tools/buildkit_import.zig`, Zig protocol/import/process code, configured importer paths, and release artifacts only after every caller and release/proof path is moved and native-qualified.

## Mandatory integration and qualification sequence

1. Specify the caller protocol crate packaging and service UID/socket authorization. Resolve the same-UID constraint before production wiring.
2. Add the atomic archive-import-and-pin operation and verified generic result facts required by the caller receipt. Add protocol tests for idempotent replay and GC/crash safety.
3. Replace buildd's duplicated protocol definitions/transport with `artifactd-protocol`; add durable storage for artifactd's allocated operation token, pin identity, generic facts, and a buildd-owned provenance receipt.
4. Wire the real BuildKit OCI-export completion path to open the private archive and send its FD. Preserve business IDs only in buildd, keep the build attempt pending on ambiguous outcomes, and replay the same token after restart.
5. Add non-ignored Linux integration tests that launch a real artifactd under the intended service identities. Cover FD import, lost response/replay after buildd restart, crash before/after artifact admission and receipt publication, import-versus-GC race, pin release, OCI facts/receipt binding, authenticated registry push and pull, auth failure, and credential redaction. Exercise both linux/amd64 and linux/arm64 images.
6. Replace API publisher/importer config, release/stage scripts, recovery, and proof contracts with the direct caller contract. Run the migration/cutover proofs on the real executable and package bundle.
7. Move Node's Artifact lifecycle to the external protocol and qualify it. Only after all callers, native tests, failure/recovery gates, and release packaging pass may old Zig Artifact/importer/protocol/process-launch sources and build requirements be removed.

Current evidence does not close these steps: the buildd real-daemon test is ignored unless explicitly provisioned, it is not called by the production build path, and its optional registry section is a test hook. Source presence and protocol-shape similarity are not caller integration or qualification.
